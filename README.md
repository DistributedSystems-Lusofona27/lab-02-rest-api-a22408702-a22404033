## What this project is

A Spring Boot 4.1 application (Java 25) exposing two REST APIs, Product and Supplier, each with full CRUD, Jakarta Bean Validation on the request DTOs, RFC 9457 `ProblemDetail` error responses with per-field validation messages, and OpenAPI documentation generated by springdoc. Data is stored in memory in a `ConcurrentHashMap` and is lost when the application stops.

## Build and run

```bash
./mvnw clean package
./mvnw spring-boot:run
```

On Windows use `.\mvnw.cmd` instead of `./mvnw`. The service listens on port **8081**.

## Endpoints

| API | Base path |
|---|---|
| Products | `http://localhost:8081/api/v1/products` |
| Suppliers | `http://localhost:8081/api/v1/suppliers` |

Swagger UI: `http://localhost:8081/swagger-ui.html`

The Bruno collection is in `bruno/`. Select the `Local` environment and run the whole collection against a freshly started service.

## What I found hardest

Getting Lombok to work in IntelliJ took longer than expected, because the command-line build succeeded while the IDE kept showing errors until the Lombok plugin was installed. Sending JSON with curl from PowerShell was also confusing, since the quoting broke the request body, so we ended up using Bruno for testing. Finally, understanding why the validation errors did not list the fields until the exception handler had `@Order(Ordered.HIGHEST_PRECEDENCE)` was the most useful thing we learned in this lab.
